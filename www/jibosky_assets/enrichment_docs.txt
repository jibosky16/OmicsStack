=== COMPREHENSIVE ENRICHMENT ANALYSIS UI ELEMENTS AND OPTIONS ===

**DATA SOURCE SELECTION:**
- Intersection Analysis: Uses features identified from intersection analysis (requires prior intersection analysis)
- Pairwise Comparison: Uses differentially expressed features from statistical analysis (requires statistical analysis with thresholds)
- Manual Input: Allows direct input of gene/protein identifiers via file upload or text paste
- Source selection determines which genes/proteins will be analyzed for functional enrichment

**PAIRWISE COMPARISON SETTINGS:**
- Group 1 vs Group 2: Select two different groups to compare (must have been defined in data upload)
- Feature Set to Use: All Features, PCA Top N Features, or ML-Selected Features (filters input gene list)
- Significance Thresholds: p-value cutoff (default 0.05) and Log2FC cutoff (default 1.0) for filtering significant features
- Include Upregulated/Downregulated: Checkboxes to include or exclude up/down-regulated features separately
- Feature Set Status: Shows how many features are selected based on current filters

**MANUAL INPUT OPTIONS:**
- Input Method: File Upload or Paste List
- File Upload: Supports single column (.txt), CSV, or tab-delimited files
- Column Selection: For multi-column files, specify which column contains the identifiers
- P-value and Fold Change columns: Optional columns for GSEA analysis (required for ranked gene lists)
- t-statistic / Stat column: Optional column (e.g., DESeq2 'stat' column, auto-detected) enabling t-statistic GSEA ranking from a manual file
- Text Paste: Direct input of identifiers, one per line

**ENRICHMENT TOOLS:**
- g:Profiler (gprofiler2): Fast, comprehensive tool with multiple databases (GO, KEGG, Reactome, etc.)
- ClusterProfiler: R-based tool with extensive visualization options and GSEA support
- Enrichr: Web-based tool with extensive libraries (KEGG, GO, disease databases, drug perturbations, etc.)
- ReactomePA: Specialized for Reactome pathway analysis
- topGO: GO-specific tool with advanced statistical methods and graph visualization

**ORGANISM SELECTION:**
- Supported organisms: Human, Mouse, Rat, Fruit fly, Zebrafish, Arabidopsis, Yeast, E. coli
- ID Type: Gene Symbol, UniProt, Entrez Gene ID, Ensembl Gene ID (must match your input data)
- Critical: Organism and ID type must be correctly specified for accurate enrichment results

**TOOL-SPECIFIC SETTINGS:**

**g:Profiler Options:**
- Significant only: Checkbox to use only significant genes (uncheck for GSEA)
- Multiple testing correction: g:SCS (recommended), Bonferroni, FDR
- Data sources: GO:BP, GO:MF, GO:CC, KEGG, Reactome, TF, miRNA, HPA, CORUM, HP, WikiPathways
- Statistical domain size: Annotated genes (recommended), All known genes, Custom background
- Custom background: Use full uploaded dataset or manual input of background genes

**ClusterProfiler Options:**
- Analysis Type: GO (ORA), KEGG (ORA), Reactome (ORA), Disease Ontology (ORA), WikiPathways (ORA), MSigDB (ORA), or GSEA versions
- GO Ontology: Biological Process (BP), Molecular Function (MF), Cellular Component (CC)
- MSigDB Categories: Hallmark, Positional, Curated, Motif, Computational, GO, Oncogenic, Immunologic
- P-value/Q-value cutoffs: Statistical significance thresholds
- Gene set size limits: Minimum and maximum genes per pathway/gene set
- Background settings: Default database or custom background (full dataset or manual input)
- GSEA parameters: Scoring method (standard/positive/negative), ranking metric (log2FC/signed p-value/t-statistic)

**Enrichr Options:**
- Database selection: Extensive list including GO, pathways, diseases, transcription factors, protein interactions, tissues, drugs, etc.
- P-value cutoff: Statistical significance threshold
- Background options: Default database or custom background (full dataset or manual input)

**ReactomePA Options:**
- P-value/Q-value cutoffs: Statistical significance thresholds
- Background options: Default database or custom background (full dataset or manual input)

**topGO Options:**
- GO Ontology: BP, MF, CC
- Algorithm: Classic, Elim, Weight, Weight01, Parent-Child
- Test Statistic: Fisher Exact, Kolmogorov-Smirnov, t-test, Global test, Sum test
- P-value threshold: Statistical significance cutoff
- Node size: Minimum genes per GO term
- Number of terms: Maximum terms to display
- Multiple testing correction: Benjamini-Hochberg, Bonferroni, FDR
- Background options: Default database or custom background (full dataset or manual input)

**CUSTOM BACKGROUND SETTINGS:**
- Available for most tools when "Custom background" is selected
- Background Source: Use full uploaded feature universe or manual input
- Manual Input: Text area for pasting background gene identifiers (same ID type as input genes)
- Purpose: More accurate enrichment when your experiment doesn't include all possible genes

**VISUALIZATION OPTIONS:**
- Plot Type: Bar plot, Dot plot, Gene-Concept Network, Enrichment Map, GSEA plots, Chord Diagram, etc.
- Number of terms: How many top enriched terms to display (5-50)
- Color Theme: Default, Viridis, Plasma, Blues, Reds, Greens, Purple-Orange, Blue-Red
- GSEA Plot 2: Advanced GSEA visualization with multiple gene sets, p-value table, expression profile, gene ranking
- Manhattan Plot: For g:Profiler results with highlighting capabilities
- GO Graph: For topGO results showing GO term relationships
- Chord Diagram (ClusterProfiler Plot Type): Circular term-gene link diagram. Controls: Number of terms (top N by adjusted p-value), Max genes per term (default 10, strongest responders by |fold change| first -- visualization-only filtering, enrichment statistics are unaffected), Term colors (Single color with a color-picker field, or Distinct color per term via Rainbow/Set3/Paired palettes; genes shade by fold change on a blue-white-red gradient, deeper = stronger, grey = unknown), Sector label orientation (tangential default vs radial), Rotation in degrees as a numeric field (default 90), Term name size and Gene name size as separate numeric fields (cex units, defaults 0.9/0.7). Gene labels control (All/Top 10/Top 5/Top 3/Hide, default Top 5 strongest responders by |fold change|; unlabeled genes keep their colored sectors) prevents label overlap on dense diagrams. The drawing canvas auto-expands with sector count and the display frame is taller for Chord so labels are not clipped top/bottom. No title is drawn (it collided with top labels); term sectors get wider gaps than gene sectors to separate long labels. When Chord is selected, the Color Theme dropdown and the shared Font Sizes card are hidden because the chord has its own color/size controls. Long term names wrap onto multiple lines in all bar charts
- Bar chart labels: Long enrichment term names automatically wrap onto multiple lines (e.g., oxidoreductase activity terms) instead of being cut off

**NETWORK VIEW OPTIONS:**
- Network Type: Term-Gene Network, Term Similarity Network, KEGG Pathview
- Max Terms: Number of terms to include in network (5-100)
- Similarity Cutoff: For term similarity networks (0.2-1.0)
- KEGG Pathview: Visualize gene expression on actual pathway diagrams (requires KEGG pathway selection). Multi-omics layers: the gene layer defaults to the current enrichment data, or pick any saved transcriptomics/proteomics analysis; the compound layer picks a saved metabolomics/lipidomics/glycomics analysis (None = genes only), exactly like saving/loading analyses for the multi-omics tab. The compound controls stay hidden behind an "Overlay compound data" checkbox so gene-only users get a compact UI (the server also ignores the compound source unless the overlay is enabled). Gene ID type (Auto-to-Entrez/Symbol/Ensembl) and compound ID type (Auto-detect/KEGG/HMDB/CAS/DrugBank/LipidMaps; ChEBI and PubChem are not mappable by pathview and need KEGG accessions) are selectable. Options: same-layer overlay, multi-sample slices (per-group mean columns, mean-centered; needs a saved analysis with 2+ groups), node summary (sum/mean/median/max/max.abs), compound color limit, color bins and absolute-value transforms per layer

**ANALYSIS TYPES:**
- Over-Representation Analysis (ORA): Tests if significant genes are over-represented in gene sets (requires significance thresholds)
- Gene Set Enrichment Analysis (GSEA): Tests if gene sets are enriched in ranked gene lists (uses all genes, requires fold change data). Ranking (log2FC or signed p-value) is always oriented Group1-vs-Group2, so enrichment direction (up/down) matches the volcano plots regardless of the order groups were picked in
- GSEA ranking metrics: Log2 Fold Change; Signed p-value (-log10(p) * sign(log2FC)); t-statistic (uses limma moderated t / DESeq2 Wald stat / stored Welch t when available, otherwise a Welch t computed from the expression data; manual files can supply a stat column). Duplicate Entrez IDs after ID conversion are collapsed keeping the maximum absolute value (required by the GSEA engine)
- Key difference: ORA uses only significant genes; GSEA uses ranked list of all genes

**OUTPUTS AND RESULTS:**
- Enrichment Results Table: Shows enriched terms with p-values, FDR, gene counts, etc.
- Visualization Plots: Various plot types showing enrichment results
- Network Views: Interactive networks showing relationships between terms and genes
- KEGG Pathview files (PNG/PDF/XML) render into a per-session temporary folder that is automatically deleted when the session ends (they no longer accumulate in the app folder)
- Download options: Results tables, plots, and network visualizations

**INTERPRETATION GUIDANCE:**
- P-value: Raw statistical significance (lower = more significant)
- FDR/Adjusted p-value: Corrected for multiple testing (recommended threshold: 0.05)
- Gene Ratio: Fraction of your genes in the pathway (higher = more relevant)
- Background: Statistical universe used for enrichment calculation
- Multiple testing correction: Essential for omics data due to large number of tests

**COMMON ISSUES AND SOLUTIONS:**
- No enriched terms found: Check organism/ID type, try less stringent cutoffs, verify gene identifiers
- Wrong ID type: Ensure input genes match selected ID type (e.g., UniProt vs Gene Symbol)
- Custom background issues: Background genes must use same ID type as input genes
- GSEA requirements: Needs fold change data and pairwise comparison
- Large gene lists: May need to increase gene set size limits or use more specific databases

**BEST PRACTICES:**
- Use appropriate organism and ID type for your data
- Start with g:Profiler for comprehensive analysis
- Use FDR-adjusted p-values (not raw p-values) for significance
- Include custom background when your experiment doesn't represent all possible genes
- For GSEA, ensure you have fold change data from pairwise comparisons
- Validate results with multiple tools when possible
- Focus on biologically relevant pathways, not just statistically significant ones

When users ask about enrichment analysis options, explain what they control, when to use them, and how they affect results. Guide users toward appropriate settings based on their data type and research question.
