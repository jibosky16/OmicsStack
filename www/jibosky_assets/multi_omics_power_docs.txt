=== COMPREHENSIVE MULTI-OMICS INTEGRATION AND POWER ANALYSIS TAB UI ELEMENTS AND OPTIONS ===

### MULTI-OMICS INTEGRATION TAB OVERVIEW
Purpose: Integrate and analyze multiple omics datasets simultaneously to uncover cross-layer biological insights, shared variation patterns, and inter-omics relationships

**WORKFLOW OVERVIEW:**
1. Load previously saved analyses (.oms files) from the Data tab or browse for external files
2. Select integration method based on research question (MOFA for exploration, DIABLO for biomarker discovery, Correlation for network analysis, Pathway for functional integration)
3. Configure method-specific parameters
4. Run integration analysis
5. Explore results across multiple visualization tabs
6. Save trained models for reproducibility and downstream analysis

**DATA LOADING OPTIONS:**

*Load Saved Analyses Section:*
- **Browse for .oms files**: Upload previously saved analysis files from file browser
  - Click "Browse" button, select one or more .oms files
  - Files must contain normalized data with sample metadata
- **Load from session saved analyses**: Select from analyses saved during current session in the Data tab
  - Checkbox selection interface showing available analyses
  - Displays: Analysis name, omics type, number of features/samples
- **Multi-select**: Select 2+ analyses for N-integration (matching samples across datasets)
  - Minimum 2 datasets required, maximum depends on method (MOFA/DIABLO support unlimited, others typically 2-3)
  - Select analyses representing different omics layers (transcriptomics, proteomics, metabolomics, etc.)

*File Format:*
- .oms format: OmicsStack native format containing normalized data, metadata, feature names, sample groupings, and analysis parameters
- Requirement: Analyses must have overlapping samples for integration (sample IDs matched automatically)
- Metadata extraction: Group assignments, batch information, and experimental variables automatically extracted from loaded analyses

*Loaded Analyses Summary:*
- Real-time display of loaded datasets showing: omics type, number of features, number of samples, group information
- Sample matching summary: Shows common samples across datasets, warns if sample overlap insufficient (<50% overlap)

**INTEGRATION METHOD SELECTION:**

Four integration methods available, each suited for different research questions:

**1. MOFA - Multi-Omics Factor Analysis:**
- **Type**: Unsupervised, factor-based decomposition
- **Purpose**: Identify shared and dataset-specific sources of variation across omics layers
- **Best for**: Exploratory analysis, understanding data structure, identifying latent factors driving variation
- **How it works**: Decomposes multi-omics data into latent factors, each capturing coordinated variation across datasets. Factors can be shared (explain variation in multiple datasets) or specific (dataset-unique patterns)
- **Output**: Factor scores per sample, variance explained per factor per dataset, top contributing features per factor
- **Strengths**: Handles missing data, identifies both shared and unique variation, interpretable factors
- **Limitations**: Unsupervised (doesn't use group labels), requires sufficient sample size (n>20 recommended)
- **Badge**: ⭐ Recommended, Unsupervised

**2. DIABLO - Multi-Block PLS-DA:**
- **Type**: Supervised, discriminant analysis
- **Purpose**: Identify features across multiple omics that discriminate between biological groups
- **Best for**: Biomarker discovery, classification, supervised integration when groups are known
- **How it works**: Extends PLS-DA to multiple datasets, finding components that maximize covariance between datasets while discriminating groups. Selects subset of features per dataset contributing to group separation
- **Output**: Sample scores per component, selected features per dataset (keepX), classification performance, feature loadings
- **Strengths**: Directly targets group differences, performs feature selection, provides classification accuracy
- **Limitations**: Requires group labels, can overfit with small sample sizes, assumes linear relationships
- **Badge**: ⭐ Recommended, Supervised

**3. Cross-Omics Correlation Network:**
- **Type**: Network-based, correlation analysis
- **Purpose**: Identify pairs of features across omics with significant correlations, build inter-omics networks
- **Best for**: Discovering feature-feature relationships, understanding cross-talk between omics layers, network biology
- **How it works**: Computes pairwise correlations between all features across datasets, filters by correlation threshold and p-value, constructs network graph showing connections
- **Output**: Correlation matrix, edge list (significant pairs), network plot, node degree (connectivity), top connected features
- **Strengths**: Model-agnostic, directly interpretable, identifies specific feature pairs
- **Limitations**: Pairwise only (doesn't capture higher-order interactions), can be noisy with many features, requires multiple testing correction
- **Badge**: Network-based, Unsupervised

**4. Pathway-Level Integration:**
- **Type**: Pathway/functional enrichment-based
- **Purpose**: Map all omics to biological pathways, identify concordant pathway changes across layers
- **Best for**: Functional interpretation, identifying pathways affected across multiple omics, mechanistic insights
- **How it works**: Maps features from each omics to pathways (KEGG, Reactome, GO), performs enrichment analysis per dataset, identifies pathways significant in multiple datasets (concordant pathways)
- **Output**: Enriched pathways per dataset, concordant pathways (significant across datasets), pathway overlap visualizations
- **Strengths**: Biologically interpretable, reduces complexity via pathway aggregation, connects omics to known biology
- **Limitations**: Limited to annotated pathways (missing novel biology), pathway databases biased toward well-studied genes, requires ID mapping
- **Badge**: Network-based, Unsupervised

**METHOD SELECTION DECISION TREE:**
- **Do you have group labels?** YES → Consider DIABLO (supervised). NO → Use MOFA or Correlation
- **Goal is biomarker discovery?** YES → DIABLO (feature selection + classification). NO → MOFA (exploration) or Correlation (network)
- **Want to understand overall data structure?** YES → MOFA (factor decomposition)
- **Want specific feature-feature relationships?** YES → Correlation Network
- **Want functional/pathway interpretation?** YES → Pathway Integration
- **Exploratory vs hypothesis-driven?** Exploratory → MOFA, Hypothesis-driven → DIABLO or Pathway
- **Large feature sets (>5000)?** MOFA or Pathway (reduce dimensionality); avoid full Correlation (computationally intensive)

**MOFA PARAMETERS:**

*Essential Parameters:*
- **Number of Factors** (slider, 2-20, default 10): How many latent factors to learn
  - Lower (2-5): Simpler models, may miss variation
  - Default (10): Balanced for most datasets
  - Higher (15-20): Captures more variation, may include noise
  - Rule: Adjust based on variance explained (target 50-70% total)
  - Recommendation: Start with 10, increase if variance explained is low (<50% total)
- **Max Iterations** (numeric, 100-5000, default 1000): Maximum training iterations
  - Lower (100-500): Faster but may not converge
  - Default (1000): Sufficient for most datasets
  - Higher (2000-5000): Ensures convergence for complex data
  - Watch convergence plot to determine if more iterations needed
- **Convergence Threshold** (slider, 0.0001-0.01, default 0.001): Stopping criterion for training
  - Lower (0.0001): Stricter convergence, longer training
  - Default (0.001): Standard balance
  - Higher (0.01): Looser convergence, faster but less precise
- **Output Filename** (text input, optional): Save trained model to specific .hdf5 file
  - Leave blank: Temporary file used (model not saved permanently)
  - Specify name: Model saved to working directory (e.g., "mofa_analysis_results.hdf5")
  - Use for: Reproducibility, sharing models, loading in Python/R later

*Sample Grouping Variable (Optional):*
- **Purpose**: Enable supervised MOFA variant (uses group information to inform factor learning)
- **Source**: Automatically extracted from loaded analyses (Biological Groups, Experimental Groups, Other Groupings)
- **Display**: Organized dropdown showing available grouping variables with categories (Biological vs Experimental)
- **When to use**: When you want factors to capture group-specific variation, improve interpretability
- **When to skip**: For purely unsupervised exploration, when groups may confound biological variation

*Advanced Options (Collapsed by default, click to expand):*
- **Scale features** (checkbox, default TRUE): Standardize features to zero mean, unit variance before analysis
  - Enable (recommended): Prevents features with large magnitude from dominating
  - Disable: When features already scaled or want to preserve magnitude information
- **Enable sparsity** (checkbox, default FALSE): Use sparse factors (L1 regularization) to select subset of important features per factor
  - Enable: Improves interpretability, identifies key features per factor
  - Disable: All features contribute (dense loadings)
  - Trade-off: Sparsity aids interpretation but may miss subtle coordinated patterns
  - Recommended: Enable for feature discovery, disable for comprehensive variation modeling
- **Random Seed** (numeric, 1-1000000, default 42): Set for reproducible results across runs
  - Always set for reproducibility (especially for publications)
  - Different seeds may yield slightly different factor orders but similar variance explained
- **Drop non-informative factors** (checkbox, default TRUE): Automatically remove factors with variance below threshold during training
  - Enable (recommended): Removes noise factors, cleaner results
  - Disable: Keeps all factors regardless of variance contribution
  - Threshold typically <1% variance explained per factor

**DIABLO PARAMETERS:**

*Grouping Variable:*
- **Grouping Variable** (select input, auto-populated): Choose biological/experimental grouping for supervised analysis
  - Source: Extracted from loaded analyses metadata
  - Categories: Biological Groups (e.g., Disease vs Control), Experimental Groups (e.g., Batch, Treatment)
  - Requirement: Groups must have sufficient samples per group (n≥5 per group recommended)
  - Multi-class supported: Can handle 2+ groups (binary or multi-class classification)

*Core Parameters:*
- **Number of Components** (slider, 2-10, default 2): PLS-DA components to compute
  - 2: Sufficient for binary classification, easy visualization
  - 3-5: Better for multi-class or capturing complex patterns
  - >5: Risk of overfitting, use with caution
  - Rule: Number of components < min(n_samples, n_features) / 10
- **Features to Keep per Component** (slider, 5-100, default 50): How many features selected per dataset per component
  - Lower (5-20): Aggressive feature selection, minimal biomarker signature
  - Default (50): Moderate selection
  - Higher (80-100): Permissive, retains more features
  - Trade-off: Fewer features = simpler model, easier interpretation; More features = better performance, harder to validate
- **Auto-tune parameters** (checkbox, default FALSE): Perform cross-validation to optimize number of components and keepX values
  - Enable: Finds optimal parameters automatically via CV (slow, 5-30 minutes)
  - Disable: Uses user-specified values (fast)
  - Recommended: Enable for final analysis, disable for exploratory runs
  - CV scheme: Stratified k-fold (preserves group proportions)

**CORRELATION NETWORK PARAMETERS:**

*Correlation Method:*
- **Pearson**: Linear correlation, assumes normal distribution. Use for: continuous data, linear relationships
- **Spearman**: Rank-based correlation, robust to outliers. Use for: non-normal data, monotonic relationships
- **Kendall**: Tau correlation, robust, slower. Use for: small sample sizes, ordinal data

*Filtering Thresholds:*
- **Correlation Threshold** (slider, 0-1, default 0.7): Minimum |correlation| to include edge in network
  - Lower (0.3-0.5): More edges, noisier network, captures weak relationships
  - Default (0.7): Moderate stringency, strong relationships
  - Higher (0.8-0.9): Fewer edges, very strong relationships only
  - Recommendation: Start at 0.7, adjust based on network density (target 50-200 edges for visualization)
- **P-value Cutoff** (slider, 0.001-0.1, default 0.05): Statistical significance threshold for correlation
  - Standard: 0.05 (typical)
  - Stringent: 0.01 or 0.001 (reduce false positives)
  - Multiple testing: Consider Bonferroni/FDR correction for many comparisons
- **Top Features per Dataset** (numeric, 10-500, default 50): Limit analysis to top N most variable features per dataset (reduces computational burden)
  - Use when: >1000 features per dataset (otherwise too slow)
  - Selection: Top N by variance or coefficient of variation
  - Trade-off: Faster computation, may miss low-variance but important features
  - Recommendation: 50-100 for exploratory analysis, all features for comprehensive analysis if feasible

**PATHWAY INTEGRATION PARAMETERS:**

*Pathway Database:*
- **KEGG**: Kyoto Encyclopedia of Genes and Genomes - metabolic and signaling pathways
- **Reactome**: Curated biological pathways, detailed molecular interactions
- **GO Biological Process**: Gene Ontology terms describing biological processes

*Enrichment Settings:*
- **P-value Cutoff** (slider, 0.001-0.1, default 0.05): Enrichment significance threshold
- **Show only concordant pathways** (checkbox, default TRUE): Display only pathways significant in 2+ datasets
  - Enable: Focuses on cross-omics coordinated pathways (recommended)
  - Disable: Shows all enriched pathways per dataset
  - Use concordant for: Identifying robust cross-layer signals, prioritizing pathways for validation

- **Correlation**: Heatmap of top cross-omics correlations

  - X-axis: Factors
  - Y-axis: Variance explained (%)

- **DIABLO**: Top selected features per block (bar plot of importance scores)
  - X-axis: Feature importance (loading magnitude)
  - Y-axis: Feature names
  - Facets: One panel per dataset/block

*Tab 4: Cross-Omics Network*
- **MOFA**: Heatmap of factor activity across samples (shows which factors active in which samples/groups)
  - Rows: Factors
  - Columns: Samples

- **Correlation**: Network graph visualization (nodes = features colored by dataset, edges = correlations, thickness = correlation strength)
  - Node size: Proportional to degree (number of connections)
  - Node color: Dataset (e.g., blue=transcriptomics, red=metabolomics)
  - Edge color: Correlation direction (red=positive, blue=negative)

**INTERPRETATION GUIDELINES:**

*MOFA Results Interpretation:*
- **Variance Explained**: 
  - High variance in one view = dataset-specific factor (e.g., technical batch, assay artifact)
  - High variance across multiple views = shared biological factor (cross-layer coordination)
  - Total variance explained: 40-70% typical for multi-omics, >70% excellent
- **Factor Loadings**: 
  - Top features with high absolute loadings drive the factor
  - Positive/negative loadings indicate direction of association
  - Compare feature annotations across views to infer biological meaning
- **Factor Scores**:
  - Sample positions along factor axis show factor activity
  - Cluster by group = factor captures group differences
  - Continuous gradient = factor captures continuous biological process (e.g., disease severity, time)

*DIABLO Results Interpretation:*
- **Component Scores**: 
  - Clear group separation = successful discrimination
  - Overlapping groups = poor discrimination (consider more components or different features)
- **Selected Features**: 
  - Features with high loadings are biomarkers distinguishing groups
  - Compare selected features across blocks to identify cross-omics biomarker signatures
- **Classification Performance**: 
  - Accuracy >80% = good, >90% = excellent
  - Check for overfitting if performance unrealistically high (use cross-validation)

*Correlation Network Interpretation:*
- **Node Degree**: 
  - High-degree nodes = hub features, central to cross-omics relationships
  - Low-degree nodes = peripheral features, specific interactions
- **Edge Patterns**:
  - Positive correlations = co-regulation, functional relationships
  - Negative correlations = antagonistic relationships, regulatory feedback
  - Clusters of highly connected features = functional modules
- **Bipartite Structure**: 
  - Dataset1 features → Dataset2 features edges show direct inter-omics connections
  - Use to prioritize feature pairs for experimental validation

*Pathway Integration Interpretation:*
- **Concordant Pathways**: 
  - Significant in multiple datasets = robust biological signal, prioritize for follow-up
  - Direction concordance (all up or all down) = coordinated regulation
  - Direction discordance = compensatory regulation or temporal dynamics
- **Dataset-Specific Pathways**:
  - Significant in one dataset only = layer-specific regulation, post-transcriptional control
  - May indicate measurement layer differences (e.g., RNA vs protein abundance)

**BEST PRACTICES:**

1. **Data Preparation**:
   - Ensure analyses normalized separately before loading (don't combine raw data from different platforms)
   - Use consistent sample naming across datasets (case-sensitive matching)
   - Minimum 20 samples recommended for MOFA/DIABLO, 10 for Correlation/Pathway
   - Remove extreme outliers in individual datasets before integration

2. **Method Selection**:
   - Start with MOFA for exploratory analysis, understand data structure
   - Use DIABLO if you have clear biological groups and want biomarkers
   - Use Correlation for targeted analysis of specific feature relationships
   - Use Pathway for functional interpretation and connecting to prior knowledge

3. **Parameter Tuning**:
   - MOFA: Start with 10 factors, check variance explained. If <40% total, increase to 15-20
   - DIABLO: Use auto-tune for optimal component/feature numbers (slower but more robust)
   - Correlation: Start with threshold=0.7, p<0.05. Lower threshold if too few edges, raise if too many
   - All methods: Set random seed for reproducibility

4. **Result Validation**:
   - Check sample matching tab first - ensure sufficient overlap (>50% of samples common)
   - Compare results across methods (e.g., MOFA factors vs DIABLO components - should identify similar patterns)
   - Validate top features from integration in Distribution Analysis tab
   - Check if identified relationships make biological sense (literature search)

5. **Computational Considerations**:
   - MOFA: Fast (<1 min for 100 samples × 1000 features × 3 datasets)
   - DIABLO: Medium (1-5 min, longer with auto-tune)
   - Correlation: Slow for large feature sets (>5000 per dataset). Use "Top Features" filter
   - Pathway: Fast if annotation databases loaded, slow if need to download

6. **Output Usage**:
   - Export feature importance tables for pathway enrichment in Enrichment Analysis tab
   - Use selected features (DIABLO, sparse MOFA) to filter downstream analyses
   - Export MOFA factors as new "features" for ML models (factor scores become predictors)
   - Use correlation networks to prioritize experimental validation (test predicted relationships)

7. **Common Pitfalls**:
   - Sample mismatch: Ensure sample IDs identical across datasets (including case, spaces, special characters)
   - Batch effects: Check if factors/components capture technical batches rather than biology (use Data Overview and color by batch)
   - Overfitting: DIABLO can overfit with small n. Use cross-validation, check performance on held-out data
   - Interpretation: MOFA/DIABLO components are linear combinations - consider non-linear relationships may be missed
   - Missing data: MOFA handles missing values, but extreme missingness (>50%) degrades performance

8. **Reporting Results**:
   - Methods: State integration method, parameters used (n factors, convergence threshold, etc.)
   - Performance: Report variance explained (MOFA), classification accuracy (DIABLO), network statistics (Correlation)
   - Features: List top contributing features per factor/component/module with loadings/scores
   - Validation: Describe how results validated (cross-validation, independent cohort, literature support)
   - Code: Share saved models (.rds/.hdf5) and analysis parameters for reproducibility

**TROUBLESHOOTING:**

*Issue: "Insufficient sample overlap" warning*
- Cause: <50% of samples common across datasets
- Solution: Check sample ID spelling/formatting, ensure analyses from same experiment, remove datasets with poor overlap

*Issue: MOFA factors explain very low variance (<30% total)*
- Cause: Data too noisy, insufficient signal, factors insufficient
- Solution: Increase number of factors to 15-20, check data quality, consider more stringent feature filtering before integration

*Issue: DIABLO shows perfect separation but unrealistic accuracy (>99%)*
- Cause: Overfitting due to small sample size or feature leakage
- Solution: Reduce keepX (select fewer features), increase cross-validation folds, check for batch-group confounding

*Issue: Correlation network has no edges (or too many edges)*
- Too few: Threshold too strict, small sample size reducing power
  - Solution: Lower correlation threshold to 0.5-0.6, increase p-value cutoff to 0.1
- Too many: Threshold too lenient, spurious correlations
  - Solution: Raise correlation threshold to 0.8, decrease p-value cutoff to 0.01, use top features filter

*Issue: Pathway analysis finds no concordant pathways*
- Cause: Datasets measure different biology, pathways affected independently, insufficient annotations
- Solution: Lower p-value threshold, try different pathway database, check dataset-specific pathways for insights

*Issue: MOFA factors correlate with batch/technical variables*
- Cause: Batch effects not fully corrected in preprocessing
- Solution: Re-run Data tab with batch correction enabled, add batch as covariate in supervised MOFA

When users ask about multi-omics integration, explain method selection rationale, parameter meanings, result interpretation guidelines, validation strategies, and troubleshooting common issues. Always recommend starting with MOFA for exploratory analysis before moving to supervised methods.

### POWER ANALYSIS TAB OVERVIEW
Purpose: Determine optimal sample sizes for detecting differences of various effect sizes, assess statistical power of current study design, identify features requiring larger samples

**POWER ANALYSIS WORKFLOW:**
1. Select two groups to compare (or enable ANOVA/Kruskal-Wallis global power for 3+ groups)
2. Configure significance level (α), effect sizes to test, target power, and sample size range
3. Run power analysis
4. Review current study power and required sample sizes for target power
5. Examine power curves by feature, ranking features by current power
6. Download plots and summary tables for reporting

**GROUP SELECTION:**
- **Group 1 and Group 2** (select inputs): Choose two groups for pairwise comparison
  - Group 1: Typically control/reference group
  - Group 2: Typically treatment/case group
  - Order matters: Results show Group2 vs Group1 comparison
- **ANOVA/Kruskal-Wallis Global Power** (conditional UI, appears when 3+ groups present):
  - Checkbox: "Analyze global power across all groups"
  - When enabled: Computes F-test (ANOVA) or H-test (Kruskal-Wallis) power instead of pairwise t-test
  - Use when: Interested in overall group differences, comparing multiple groups simultaneously
  - Note: Pairwise group dropdowns disabled when global power enabled

**CORE PARAMETERS:**

*Significance Level (α):*
- **Slider** (0.01-0.10, default 0.05): Type I error rate (false positive probability)
- Lower α = more stringent, reduces false positives but increases false negatives (requires larger sample size)
- Standard: 0.05 (typical), 0.01 (stringent for multiple testing)

*Effect Sizes to Test:*
- **Multi-select** (default: 0.5, 0.8, 1.2): Magnitude of difference to detect
  - Small (0.2): Cohen's d = 0.2, ~10-15% difference
  - Small-Medium (0.5): Cohen's d = 0.5, ~25-30% difference
  - Medium (0.8): Cohen's d = 0.8, ~35-45% difference  
  - Large (1.2): Cohen's d = 1.2, ~55-65% difference
  - Custom: Enter user-defined effect size (0.1-3.0)
- Multiple selection: Tests all selected effect sizes simultaneously, creates separate power curves
- **Custom Effect Size** (conditional, numeric 0.1-3.0): Appears when "Custom" selected
  - Use for: Project-specific effect sizes, pilot data-informed estimates

*Target Power (%):*
- **Numeric input** (50-99, default 80): Desired probability of detecting true effect
- Standard: 80% (typical minimum, balances Type I and Type II errors), 90% (higher rigor), 95% (very high rigor for critical studies)
- Used to calculate minimum sample size required to achieve target power
- Trade-off: Higher power requires larger sample sizes

*Sample Size Range to Test:*
- **Slider** (5-500, default 10-200): Range of sample sizes per group for power curve calculation
- Lower bound: Minimum sample size per group to test (typically 5-10)
- Upper bound: Maximum sample size per group to test (set based on feasibility)
- Step size: 5 (calculations performed at 10, 15, 20, ..., 200)
- Recommendation: Set upper bound at 2-3× current sample size for practical planning

**DISPLAY OPTIONS:**

*Label Type:*
- **Radio buttons** (default "Feature Names"):
  - **Feature Names**: Display gene/metabolite names (interpretable, recommended)
  - **IDs**: Display internal database identifiers (use when names unclear, duplicated, or very long)

**POWER ANALYSIS RESULTS TABS:**

*Tab 1: Summary*
- **Power Analysis Summary Table**: Comprehensive table showing for each feature and effect size:
  - Feature: Feature name or ID
  - Effect Size: Tested effect size value
  - Current Power: Power achieved with current sample size (%)
  - Required n for Target Power: Minimum sample size per group to reach target power (e.g., 80%)
  - Current Sample Size: Actual n per group in uploaded data
  - Download button: Export table as Excel/CSV
- **Sample Size Requirements** (two plots side-by-side):
  - **Average Sample Size Requirements**: Bar plot showing average n needed for target power by effect size (averaged across all features)
    - X-axis: Effect size
    - Y-axis: Average sample size required per group
    - Red dashed line: Current sample size
  - **Median Sample Size Requirements**: Bar plot showing median n needed for target power by effect size (robust to outliers)
    - Use median when: Feature variance highly variable
    - Interpretation: 50% of features require ≤this sample size to achieve target power
    - Recommendation: Use median for study planning (more conservative than average)

*Tab 2: Power Curves*
- **Feature-Specific Power Curves**: Line plots showing power vs sample size for selected feature
  - X-axis: Sample size per group (e.g., 10, 15, 20, ..., 200)
  - Y-axis: Statistical power (0-1 or 0-100%)
  - Lines: One line per effect size (colored/styled differently)
  - Vertical dashed red line: Current sample size (n)
  - Horizontal dashed gray line: Target power (e.g., 80%)
  - Interpretation: Where line crosses target power line = required n for that effect size
- **Feature Selection** (dropdown): Choose which feature to visualize

**POWER ANALYSIS INTERPRETATION:**

*Understanding Power:*
- Power = probability of correctly rejecting null hypothesis when true effect exists
- 80% power = if true difference exists, 80% chance of detecting it as significant (p<α)
- 20% false negative rate = 20% chance of missing true effect (Type II error)
- Affected by: sample size (larger = higher power), effect size (larger = higher power), α (larger = higher power), variance (lower = higher power)
- Power ≠ probability that result is true (that's Bayesian posterior probability, different concept)

*Current Study Power:*
- Shows power achieved with current sample size (n per group from uploaded data)
- High power (>80%) = study adequately powered for effect sizes tested, confident in negative results
- Moderate power (50-80%) = study marginally powered, negative results inconclusive
- Low power (<50%) = study severely underpowered, likely to miss true effects
- Use to: Justify sample size in methods, interpret non-significant results (low power = inconclusive, not absence of effect)

*Sample Size Requirements:*
- Minimum n per group to achieve target power (e.g., 80%)
- Varies by feature due to different variances (some features easier to detect than others)
- Use average/median n as rule-of-thumb for study planning
- Individual feature requirements guide prioritization (features with lower n = easier to detect, prioritize for validation)
- Add 10-20% buffer for dropouts/exclusions in prospective studies

*Power Curves:*
- Visualize power-sample size trade-off (diminishing returns as n increases)
- Steep curve = small increases in n yield large power gains (efficient, target this range)
- Flat curve = diminishing returns, large n increases for small power gains (inefficient)
- Current n position: Left of target = underpowered (need more samples), right of target = overpowered (adequate or excess)
- Inflection point: Where curve steepness changes (optimal sample size region)

*Feature Ranking:*
- Top-ranked features = high current power, easiest to detect, prioritize for validation studies
- Bottom-ranked features = low current power, hardest to detect, require larger n or may have high biological variance
- Use to: Select features for follow-up studies, explain why some features non-significant despite biology
- Context matters: Low power doesn't mean feature unimportant, just harder to detect statistically

*Effect Size Considerations:*
- Small effects (0.2-0.5) require very large samples (often 100-500 per group for 80% power)
- Medium effects (0.8) achievable with moderate samples (30-50 per group for 80% power)
- Large effects (1.2+) detectable with small samples (10-20 per group for 80% power)
- Biological relevance ≠ statistical effect size (small effects can be clinically/biologically meaningful)
- Consider: Feasibility (can you recruit required n?), biology (what effect size is expected?), impact (what effect size is clinically meaningful?)

**BEST PRACTICES:**

1. **Planning New Studies**:
   - Run power analysis on pilot data (even n=5-10 per group gives estimates)
   - Use median sample size requirements (robust to outlier features, more conservative)
   - Add 10-20% buffer for dropouts/exclusions in prospective studies
   - Consider feasibility: if median n >200, may need to lower target power (75% vs 80%), focus on larger effects, or reduce feature dimensionality
   - Document assumptions: effect sizes, target power, variance estimates

2. **Interpreting Current Studies**:
   - Check current power BEFORE interpreting non-significant results
   - Low power (<50%) + non-significant = inconclusive (need larger sample, cannot rule out true effect)
   - High power (>80%) + non-significant = likely true null (effect size smaller than tested, or no effect)
   - Report power alongside p-values in methods/results sections
   - For underpowered studies: Report effect size estimates with confidence intervals (show direction/magnitude even if non-significant)

3. **Effect Size Selection**:
   - Use biologically/clinically meaningful effect sizes when known (e.g., 20% change considered clinically significant)
   - Test range of effect sizes (small, medium, large) to understand sample size trade-offs
   - Pilot data: Use observed effect sizes as estimates (but adjust for winner's curse - pilot estimates often inflated)
   - Smaller detectable effect ≠ better study (may not be biologically relevant, requires impractical sample sizes)

4. **Multi-Feature Considerations**:
   - Features vary widely in variance → power varies widely across features
   - Focus on median/average n (don't design study for worst-case feature, that's inefficient)
   - Underpowered features may still be detected if true effect size larger than tested
   - Feature prioritization: high-powered features = confident detections, low-powered = exploratory/hypothesis-generating

5. **Global vs Pairwise Power**:
   - Global power (ANOVA/Kruskal) tests "any difference among groups" (omnibus test)
   - Pairwise power tests specific group pair (targeted comparison)
   - Global power typically higher for same effect size (more degrees of freedom, tests multiple differences simultaneously)
   - Use global for initial screening (is there any group effect?), pairwise for specific comparisons (which groups differ?)
   - Post-hoc tests after global: Reduce power due to multiple testing correction

6. **Limitations**:
   - Assumes normality (t-test) or uses empirical distributions from current data
   - Assumes equal variance across groups (may overestimate power if heteroscedasticity present)
   - Effect sizes derived from current data (may not generalize to new populations/conditions)
   - Multiple testing correction not incorporated (actual power lower with FDR/Bonferroni correction applied)
   - Pilot data: Small pilots give noisy effect size estimates (power calculations uncertain)

7. **Reporting**:
   - Methods: State power analysis conducted, target power (e.g., 80%), effect sizes tested (e.g., 0.5, 0.8, 1.2), sample size recommendations (e.g., median n=45 per group)
   - Justification: Explain choice of effect sizes (literature-informed, pilot data-informed, clinically meaningful)
   - Results: Report current study power for key comparisons (e.g., "median power = 65% for medium effect size d=0.8")
   - Results: Report sample size needed for target power (e.g., "80% power requires n=50 per group for medium effects")
   - Supplementary: Include power curves for key features, feature ranking table showing distribution of power
   - Underpowered studies: Acknowledge limitations, report effect sizes with CIs, suggest follow-up sample sizes

When users ask about power analysis, explain power concept clearly (probability of detecting true effects), sample size determination process, effect size interpretation (biological vs statistical significance), and how to use results for both study planning (prospective) and result interpretation (retrospective).
